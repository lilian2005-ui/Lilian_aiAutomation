# U2 — BUILD THE SYSTEM

## System Thinking

> **Don't build what AI can build. Engineer what AI should build.**

في هذه الوحدة، انتقلت من فهم العمل إلى بناء الحل: كيف أحوّل احتياجًا حقيقيًا إلى تطبيق ويب قابل للاستخدام، وكيف أوجّه أدوات الذكاء الاصطناعي لبنائه مع الاحتفاظ بمسؤوليتي عن التفكير والتصميم والقرارات.

الهدف ليس كتابة Prompt والحصول على واجهة جميلة، بل تصميم الحل أولًا ثم توجيه الـ AI App Builder لبنائه ومراجعة ما يبنيه.

## 🎯 Capability

**System Thinking**

القدرة على تحويل مشكلة إلى نظام مصمَّم: فهم المستخدم، وتحديد الحل، وتصميم تجربة الاستخدام والنظام الداخلي، ثم كتابة Specification واضحة وتوجيه AI App Builder لتنفيذها.

---

## 🧠 What I Learned

تعلمت العمل عبر خمس طبقات مترابطة:

- **Layer 01 — Understand the User:** تحديد المستخدم والهدف والدور (User, Goal, Role).
- **Layer 02 — Define the Solution:** تحويل الاحتياج إلى Requirements وFeatures وBusiness Rules، وتحديد Scope وConstraints وحدود الـ MVP.
- **Layer 03 — Design the Experience:** رسم Use Case وUser Flow وتحديد الشاشات وSystem Behavior.
- **Layer 04 — Design the System:** تصميم Data Model (Entity, Attribute, Relationship, State)، وتحديد مهام الـ AI مقابل القواعد الثابتة (AI vs Rule)، والأتمتة وHuman-in-the-Loop، وقواعد الوصول (Role vs Permission).
- **Layer 05 — Specify & Build with AI:** كتابة Specification وتوجيه Lovable عبر دورة Define → Instruct → Build → Review → Refine.

## 🛠️ Projects

### 01 — Guided Project

**Project:** SkillBridge Lite — AI-Powered Career Fit Assistant

تطبيق ويب يساعد الطلاب والخريجين الجدد على فهم مدى توافق مهاراتهم ومشاريعهم وخبراتهم مع فرصة مهنية محددة، عبر تحليل مدعوم بالذكاء الاصطناعي يوضح نقاط التوافق والفجوات والخطوات المقترحة.

**Problem:** صعوبة تحويل المعلومات المهنية المتفرقة إلى فهم واضح للعلاقة بين الملف المهني ومتطلبات فرصة معينة.

**Solution:** تجربة بسيطة: مراجعة الملف المهني، واستكشاف الفرص، واختيار فرصة، ثم طلب AI Fit Analysis يعرض Relevant Skills وPotential Gaps وRecommended Next Steps.

**Tools:** Lovable · AI Analysis

### 02 — Independent Project

**Project:** DataSense Lite — AI-Powered Data Insights for Business Owners

نسخة MVP تجريبية لتطبيق ويب لأصحاب المشاريع، طبّقت فيه نفس تسلسل الطبقات على فكرة مختلفة.

**Problem:** أصحاب المشاريع يملكون بيانات (CSV أو Excel) لكنهم لا يملكون الوقت أو المهارة لتحليلها واستخراج قرارات منها.

**Solution:** يرفع المستخدم ملف بياناته، فيعرض التطبيق لوحة بأهم الأرقام والرسوم، مع Insights وRecommendations مبنية على البيانات. يدعم العربية والإنجليزية، ويقرأ الملف داخل المتصفح حفاظًا على خصوصية البيانات.

**Tools:** Lovable · AI Analysis

## 🔍 Engineering Focus

- من هو المستخدم، وما الهدف الذي يريد تحقيقه؟
- ما الفرق بين المشكلة والحل المقترح؟
- ما الذي يدخل ضمن الـ MVP وما الذي يقع خارجه؟
- كيف ينتقل المستخدم داخل التطبيق (User Flow)؟
- ما البيانات المطلوبة، وهل هي Static أم Persistent؟
- أين نحتاج AI وأين تكفي القواعد الثابتة؟
- كيف أراجع ما بناه Lovable وأتحقق مما يعمل فعلًا؟

---

## 📌 Key Takeaway

> **Build the smallest useful solution that solves the right problem.**

بناء التطبيقات بالذكاء الاصطناعي عملية هندسية: افهم قبل أن تبني، وحدّد قبل أن توجّه، وراجع قبل أن تقبل، وتحقق مما يعمل فعلًا وليس من المظهر فقط.
